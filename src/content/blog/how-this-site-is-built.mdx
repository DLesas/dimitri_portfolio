## What I wanted from it

I rebuilt this site with three goals, in this order. It had to be **fast on any device**, including a mid-range phone on a train. It had to be **cheap enough to forget about**: the AWS side averages around twenty cents a month. And it had to be **safe to leave running**, with no keys stored anywhere and hard caps on anything that costs money.

Each goal ended up deciding something concrete. This post walks through those decisions, roughly from the browser outwards.

## Server first, 3D after

Pages are React Server Components on Next.js 16, so the text you're reading arrived as plain HTML. Entrance animations are CSS, so they play before React has loaded. The home page's 3D network loads in its own chunk once the browser is idle after the first paint, so it never competes with the text.

### The network in four draw calls

However many nodes there are, the network takes four draw calls: other visitors' cursor glows, your cursor's glow, every connection, and every node. Nodes live in typed arrays and nothing in the render loop allocates memory, so there are no garbage-collection pauses mid-animation.

### Physics at a fixed 60 Hz

The physics steps a fixed 60 times a second, whatever the screen's refresh rate. On a 120 Hz screen that's half the work of stepping every frame, and the movement, tuned at 60 Hz, feels the same everywhere. After a stall it catches up at most four steps a frame, rather than freezing the page to replay everything it missed.

```ts
// Catch up in fixed 1/60 s steps, at most four per frame
acc = Math.min(acc + delta, STEP * MAX_STEPS_PER_FRAME);
while (acc >= STEP) {
  physicsStep(inputs, mouse, remotes, colliders);
  acc -= STEP;
}
```

### Finding connections with a grid

Checking every pair of 200 nodes takes 19,900 comparisons. Instead, nodes are sorted into cells one link-distance wide, and each is compared only with its own cell and the eight around it: about 1,600 comparisons.

## Keeping the bill near zero

The home page shows other visitors' cursors live, over AWS AppSync. Real-time traffic is the likeliest way for a hobby site to run up a surprise bill, so the cursors switch themselves off before that can happen.

### A hard spending cutoff

A small Lambda function deletes the AppSync API keys, which switches live cursors off for everyone, in three situations: when a per-minute alarm trips on message, connection or subscription counts; when a check every 15 minutes finds the month's AppSync spend past $2; or when an AWS Budgets alert fires as a backstop. Turning cursors back on is a deliberate, manual step.

<Callout>
The worst realistic case is a slow drain that stays under every per-minute alarm. Even that stops at the monthly check, a few dollars in.
</Callout>

### The contact form

Messages go out through Amazon SES using a role that Vercel assumes over OIDC, so there is no AWS key stored anywhere. That role only works from production, and it can only send email to my own inbox. Each visitor can send five messages a day, counted in DynamoDB, and a firewall rule allows five requests per IP every ten minutes on top of that.
